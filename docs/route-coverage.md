# Проверка покрытия маршрутов и месяцев — issue #2

География согласована отдельно от наличия тарифов. Все 50 городов отправления
официального списка проверяются по всем направленным парам между собой.
Дополнительные назначения: Новосибирск, Сочи, Минеральные Воды, Владивосток,
Хабаровск, Иркутск, Уфа, Омск, Челябинск, Минск, Ереван, Баку, Стамбул, Дубай
и Алматы. Уже входящие в список филиалов города не дублируются.

Получается 60 уникальных назначений и 2 950 направленных пар без поездки города
в самого себя. Авиа дополнительно сохраняет остальные доступные назначения
источника. Обратное направление не считается проверенным автоматически.

## Результаты и исходный снимок

- `data/route-coverage/scope.json` — точные списки городов и всех пар.
- `data/route-coverage/baseline-2026-11-11.json` — неизменяемые даты и SHA-256
  исходных снимков с расчётом покрытия в той же географии.
- `data/route-coverage/summary.json` — показатели до и после расширения,
  цены по видам транспорта для каждого города и статусы запросов.
- `data/route-coverage/matrix.csv.gz` — полная сжатая CSV-матрица, включая
  пустые месяцы. Это обычный UTF-8 CSV внутри gzip.
- `data/route-coverage/endpoint-investigation.json` — ответы справочников
  для Донецка, Красноармейска, Красногорска и Ясиноватой.

В матрице указаны направление, транспорт, требуемый период, фактический базовый
период, источник, дата проверки, хеш ответа, статус и причина пропуска.
`query_status` сохраняет ответ основного источника, даже если тариф взят из
исторического исследования. `supplement_query_status` показывает второй авиа-кэш.
Пустая цена не кодируется нулём. Условие `reference_available=true` означает
наличие исходного ориентира, а не пригодность для любого фильтра класса/багажа.

Чтобы открыть матрицу без дополнительных библиотек:

```python
import gzip
import shutil
with gzip.open('data/route-coverage/matrix.csv.gz', 'rb') as source:
    with open('route-coverage.csv', 'wb') as output:
        shutil.copyfileobj(source, output)
```

## Как читать пробелы

| Статус | Значение |
|---|---|
| `priced` | Есть датированный авиа-ориентир. Метод и источник указаны в строке. |
| `reference_only` | Наземный справочный ориентир есть; самостоятельного наблюдения за этот месяц нет. |
| `no_fare` | Направление не найдено в проверенном кэше. Это не доказательство отсутствия сообщения. |
| `source_unsupported` | Авиа-источник явно отклонил код отправления. |
| `no_priced_services` | Ответ получен, но извлечённой цены нет. |
| `no_direct_service` | Страница прямо сообщает, что прямых автобусов нет. Возможность пересадки не исследована этой строкой. |
| `source_page_missing` | Источник вернул HTTP 404. |
| `source_error` | Ошибка HTTP, формата или проверки ответа. |
| `unresolved_station` / `endpoint_unresolved` | Точка не сопоставлена с точным кодом; соседний город не подставлен. |
| `ambiguous_endpoint` | Регион одноимённого города резервного источника не подтверждён; тариф исключён. |
| `not_checked` | Для этого периода и источника запроса не было; в частности, текущий кэш не восстанавливает прошлые месяцы. |

Наземный статус и справочная цена относятся к дате проверки страницы.
Повторение строки для месяцев 2025–2027 годов не доказывает существование
сообщения или тарифа в каждом из этих месяцев. В таких строках `base_period`
остаётся пустым. При планировании наземная сезонность по-прежнему плоская
и явно обозначена как сценарий. Историческая помесячная наземная база не создана.

В авиа использованы два документированных метода Travelpayouts:
`prices_for_dates` и `get_latest_prices`. Оба возвращают кэш найденных
предложений, а не среднюю цену всех продаж. Сохраняются вылет, пересадки,
неизвестный багаж, источник и дата проверки. Второй метод дополнительно даёт
`found_at`; принимаются только `actual=true`, экономический класс и билет
в одну сторону. Из нескольких подходящих ориентиров сохраняется минимальный.
См. [документацию провайдера](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).

## Полнота семестров

Показатели `all_source_*_month_numbers_complete` воспроизводят исходную метрику:
наличие номеров месяцев февраль–июнь либо сентябрь–январь, даже если базовые
годы различаются. В исходном авиа-снимке это 1 086 и 711 направлений из 11 749.
Эти числа нельзя называть полнотой конкретного календарного семестра.

`spring_2027_complete` требует все пять месяцев февраля–июня 2027 года.
`autumn_2026_complete` требует сентябрь–декабрь 2026 года и январь 2027 года.
Эти показатели ограничены согласованной географией и включают найденные
исторические авиа-ориентиры с собственными датами и методами.
Они показывают наличие базовых ориентиров, а не сопоставимость багажа,
класса и горизонта покупки. В Excel соответствующие фильтры применяются отдельно.
Пропущенный месяц или участок продолжает давать недостаточность данных / `#Н/Д`.

## Четыре проблемных города

- **Донецк:** железнодорожный код `2214000` относится к подписи
  «Донецк (Донец.)». В авиа-справочнике найден `DOK` с признаком
  `has_flightable_airport=false`. Это ответ справочника на дату проверки,
  а не самостоятельно установленное отсутствие всех возможных поездок.
  Автобусный `Donetsk` не заменяется одноимённым городом Ростовской области.
  Неоднозначный резерв Atlas отключён.
- **Красноармейск:** филиал находится в Саратовской области, что подтверждено
  [отчётом филиала](https://krs.ranepa.ru/upload/krs/Otchet_o_samoobsledovanii_za_2024_%28Krasnoarmeiskii_filial%29.pdf).
  Используется отдельный автобусный идентификатор `Krasnoarmejsk_1434151`.
  Проверяется полная подпись «Красноармейск, Саратовская область».
  Неоднозначный резерв Atlas отключён. Железнодорожная подпись —
  «Красноармейск (Карамыш)», код `2020802`.
- **Красногорск:** точного железнодорожного кода в проверенной подсказке нет.
  Москва или Павшино автоматически не подставляются. Автобусы проверяются
  отдельно; расписание без цены не становится нулевым тарифом.
  Неоднозначный резерв Atlas отключён.
- **Ясиноватая:** подсказка источника вернула точную городскую подпись с кодом
  `2214034`. Она используется для отдельного сбора. Наличие кода не обещает
  ни поезда, ни цены. Соседняя станция не подставляется.

## Воспроизведение

```bash
python -m collector.route_campaign --state-dir /local/issue-2 --workers 4 --out data/parts/issue-2.json
python -m collector.planning_air --raw-dir /local/air-raw
python -m collector.planning_air_extra --state-dir /local/air-extra
python -m collector.planning_update --surface data/parts/issue-2.json
python -m collector.planning_catalog
python -m collector.route_coverage
python -m unittest discover -s tests -v
```

Первичная фиксация сравнения использует `route_coverage --baseline-dir` с
замороженными до сбора снимками. Последующие запуски используют опубликованный
baseline и отказываются незаметно сравнивать другую географию. Наземный сбор
возобновляется по журналу завершённых ответов. Для распределения предусмотрены
`--shard` и `--of`. В GitHub Actions наземные части объединяются только после
завершения всех частей, а каталог проверяется до публикации.

Исходные HTTP-ответы хранятся локально вне публичного репозитория. В Actions
они сохраняются отдельными артефактами на семь дней. В публичных данных нет
внутренних книг Excel, нормативов организации и ключей доступа.
