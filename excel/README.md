# Excel: кнопка «Обновить цены»

VBA-макрос скачивает `data/prices.json` (его публикует ночной сборщик из этого репозитория)
и заполняет рыночными ценами лист «Справочник» рабочей книги: авиабилеты, ЖД, гостиницы, курсы ЦБ.
Python и внешние библиотеки на ПК не нужны.

| Файл | Что внутри |
|---|---|
| `modPriceUpdate.bas` | сам макрос: загрузка, расчёт, запись в лист, журнал, бэкап |
| `modJson.bas` | небольшой JSON-парсер на чистом VBA (без References и DLL) |
| `modPlanning.bas` | семестровое планирование по направлениям, предпочтениям и участкам маршрута |
| `modPlanningCore.bas` | расчётное ядро: календарь, цены, предпочтения, проживание и связность маршрута; работает с массивами без доступа к листам |
| `modPlanningStorage.bas` | проверка типов каталога, безопасная запись значений и резервные копии |
| `modPlanningRouting.bas` | поиск ценового пути до трёх билетов с учётом внутренних авиапересадок |
| `clsPlanningRoutingEvents.cls` | сброс временного графа после пересчёта и изменения ячеек |

Файлы `.bas` — в кодировке **Windows-1251** с окончаниями строк CRLF: в этом виде их понимает
импорт редактора VBA. На GitHub кириллица в них может отображаться некорректно — это нормально.

## Где нормы

В коде нет ни одного порога, лимита или надбавки. Всё читается с листа **«Параметры цен»** книги:

- источник данных — URL `prices.json` (или путь к локальному файлу для проверки);
- надбавка за багаж для перелётов по РФ и за рубеж (за перелёт в одну сторону, учитывается ×2);
- очищать ли авиа-ячейки у городов без аэропорта;
- допустимые классы ЖД (`coupe:firm` — купе только в фирменных поездах, `sedentary` — сидячий, …)
  и перцентиль для «ЖД макс.»;
- фильтры гостиниц: лимит цены за ночь (РФ / зарубеж), минимум звёзд, минимальный рейтинг
  (и список городов, где звёзды и рейтинг не проверяются),
  максимальное расстояние до центра, исключение апартаментов и типов размещения —
  у каждого фильтра есть флажок «Учитывать (ДА/НЕТ)»;
- порог «старости» снимка, критерий приёмки (доля полностью обновлённых городов), число хранимых бэкапов;
- таблица сопоставления валют листа («$», «евро», «англ фунт», …) с кодами ЦБ (USD, EUR, GBP, …).

Лист «Параметры цен» живёт только в рабочей книге; сама книга в репозиторий не кладётся.

## Что делает кнопка

Строки 4–245 листа «Справочник» (строка 246 со средними не трогается). Город ищется в JSON
по паре «город + страна», для строк РФ — «город + регион» (`_` в названиях = пробел).

| Колонка | Что пишется |
|---|---|
| BO / BP | авиа туда-обратно: `air.all.median` / `air.all.p90` + багаж ×2 |
| BQ | курс ЦБ по валюте из BS; дата курса — в заголовке BQ2 |
| BR / BT / BU | гостиница: среднее отфильтрованных (руб.) / то же в валюте / максимум в валюте (числом) |
| BV / BW | ЖД туда-обратно: медиана туда + медиана обратно / перцентиль туда + обратно |

- Если в BR стоит формула `=BT*BQ`, она сохраняется, а пересчитывается BT.
- Пропуск (`status` ≠ `ok`, `stale = true`, город не найден, после фильтров пусто):
  старое значение **не затирается**, ячейка заливается светло-жёлтым, причина пишется в журнал.
  При следующем удачном обновлении жёлтая заливка снимается.
- `no_airport` / `no_station` — «не применимо», пропуском не считается.
- **Автобус, когда нет поезда.** Если ЖД для строки не получилось (`rail.status` ≠ `ok` или после
  фильтра классов пусто), а в данных `bus.status = ok`, в BV/BW пишется автобус: сред. = медиана туда +
  медиана обратно, макс. = перцентиль из параметра «ЖД: перцентиль для «макс.»» туда + обратно; если
  обратных рейсов нет — туда ×2. Значение остаётся числом (средние в строке «уточняется» считаются),
  а пометка «(автобус)» видна через числовой формат ячейки; когда снова есть поезд, формат возвращается
  к формату колонки авиа. В журнале — «ЖД: автобус (нет поезда: …)».
- **Отели без фильтра звёзд и рейтинга** для городов из параметра «Отель: города без фильтра звёзд и
  рейтинга» (через запятую, как в колонке «Город»): для них не применяются только эти два фильтра,
  остальные (лимит цены, расстояние, апартаменты, типы) остаются. В журнале — «без фильтра звёзд/рейтинга».
- Лист «Журнал обновления» перезаписывается при каждом запуске: время запуска, `generated_at`
  снимка, дата курса, сводка (полностью / частично / не обновлено, выполнен ли критерий)
  и по строке на каждый город и поле.
- Перед изменениями сохраняется копия книги в папку `_backup_цены` рядом с файлом;
  лишние старые копии удаляются.

Загрузка: `WinHttp.WinHttpRequest.5.1`, при неудаче — `MSXML2.XMLHTTP.6.0` (использует прокси Windows).

## Расчёт на даты (приблизительно)

На «Параметрах цен» есть блок «Даты поездки»: **Дата отправления** (проверка данных — не раньше
сегодняшней), **Дней в поездке** (целое ≥ 1) и вычисляемая **Дата возвращения**. Возле кнопки на
«Справочнике» эти даты показываются для справки. Живых запросов из Excel нет — всё берётся из того же
`prices.json`.

- Дата пустая — обычный режим: средние за весь период снимка.
- Дата задана:
  - авиа (BO/BP) — запись `air.by_week` за неделю, в которую попадает дата отправления, иначе
    ближайшая неделя в пределах допуска; `median` / `p90` + багаж ×2;
  - гостиница (BR/BT/BU) — окно `hotels.dated` с ближайшей к дате отправления датой заезда,
    к его `items` применяются те же фильтры. Сейчас сборщик даёт одно опорное окно (заезд через
    14 дней от даты сбора, 7 ночей), поэтому расстояние до даты отправления бывает большим — оно
    пишется в журнал («опорный заезд 04.11, ночей 7, за 46 дн. до отправления»);
  - если подходящей недели или окна нет (или в снимке ещё нет этих полей) — берутся данные без даты,
    в журнале пометка;
  - ЖД — без даты, как раньше.
- Допуски («Даты: авиа — допуск …», «Даты: отель — допуск …») — на «Параметрах цен»; допуск для отеля
  по умолчанию выключен (НЕТ = опорное окно берётся при любом расстоянии).
- В заголовках BO, BP, BR, BT, BU появляется приписка «(на даты ДД.ММ–ДД.ММ, приблизительно)»;
  когда дата очищена, приписка снимается.
- В журнале: в шапке — даты поездки и сколько городов посчитано по дате / без даты, у каждого поля —
  «опорная дата» (например «авиа: неделя с 09.11», «отель: опорный заезд 04.11, ночей 7, за 6 дн. до отправления»).

Если ставите ячейки дат вручную: формат ячеек задавайте через «Формат ячеек», а в проверке данных для
«не раньше сегодня» ссылайтесь на ячейку с `=СЕГОДНЯ()` — формулу проверки Excel ждёт на языке интерфейса.

## Как поставить в рабочую книгу

Проще всего — перенести из готовой книги-образца, где всё уже собрано:

1. Закройте лишние копии файла. Сделайте копию рабочей книги на всякий случай.
2. Откройте **обе** книги: рабочую и образец.
3. **Лист «Параметры цен»**: в образце правый клик по ярлыку → «Переместить или скопировать…» →
   книга — рабочая, поставьте галочку «Создать копию» → ОК. Проверьте значения норм.
4. **Модули**: Alt+F11 → в окне Project перетащите `modJson` и `modPriceUpdate` из проекта
   образца на проект рабочей книги (или File → Import File… и выберите `.bas` из этой папки).
   Вместе с листом переносится и блок «Даты поездки» (ячейки I2:J7 и служебная L3 с датой «сегодня»).
5. **Колонки BV/BW** на «Справочнике»: впишите заголовки в BV2/BW2 (или макрос впишет их сам при
   первом запуске), при желании скопируйте формат колонки BP и формулы средних в BV246/BW246.
6. **Кнопка**: вкладка «Разработчик» → Вставить → Кнопка (элемент управления формы) →
   нарисуйте на «Справочнике» или «Параметрах цен» → назначьте макрос `UpdatePrices`.
   (Если вкладки нет: Файл → Параметры → Настроить ленту → «Разработчик».)
7. Сохраните как `.xlsm`, нажмите кнопку, посмотрите «Журнал обновления».

Лист «Журнал обновления» создаётся автоматически.

## Отправка файла коллеге

Файл, полученный по почте или скачанный, Windows помечает «из интернета», и Excel блокирует макросы.
Получателю нужно:

1. Сохранить файл на диск и закрыть Excel.
2. Правой кнопкой по файлу → **Свойства** → внизу галочка **«Разблокировать»** → ОК.
3. Открыть файл и нажать **«Включить содержимое»** на жёлтой полосе.
4. Нажать «Обновить цены» — нужен доступ к `raw.githubusercontent.com`.

Эти же шаги есть в книге на листе «Параметры цен» (блок «Если файл получен по почте»).
Макрос не привязан к конкретному ПК: путь берётся из `ThisWorkbook.Path`, бэкап кладётся в папку
`_backup_цены` рядом с файлом у получателя. Перед отправкой стоит проверить «Данные → Изменить связи»:
ссылок на внешние книги быть не должно.

## Семестровое планирование

Установите `modJson.bas`, `modPriceUpdate.bas`, `modPlanningCore.bas`,
`modPlanningStorage.bas` и `modPlanning.bas` в копию книги. При обновлении
замените четыре модуля планирования/обновления цен актуальными версиями;
JSON-парсер сохраняется. Используется схема **3**; прежняя схема 2 отклоняется
до записи, чтобы старый публичный каталог не затёр новые данные книги.

Сначала выполните `RefreshPlanning` с URL или локальным путём к
`data/planning-excel.json`, затем `InstallPlanning`. Это компактная упаковка
тех же записей `data/planning.json`, без потери цен, типов и происхождения:
повторяющиеся строки вынесены в словарь, поля — в фиксированные колонки.
Получателю Python не нужен; данные и формулы работают офлайн.
Кнопка «Обновить плановые цены» обновляет сохранённый каталог и гостиничные базы.
До публикации схемы 3 по указанному URL кнопка может сообщать 404/несовместимую
схему; сохранённые данные при этом не меняются.
Перед записью сохраняется бэкап, после успешной операции остаётся до трёх копий.

Основной ввод остаётся на листе **«Командировки и выезды»**, в существующей
таблице; категории расходов и ссылки итогового прогноза сохраняются.

| Поля | Как заполнять |
|---|---|
| A, B | прежние семестр и год набора; год запуска читается из «Параметры»!C2 |
| C, F | число человек (поездок) и город прибытия |
| L | город отправления, без неявного значения «Москва» |
| M, N | общий ID поездки и номер участка от 1; для одиночного участка можно оставить оба пустыми |
| O, P | в строке проживания: «пребывание»/«пересадка» и число ночей на человека |
| Q, R | в транспортной строке: порядок «поезд, авиа, автобус» и багаж авиа ДА/НЕТ |
| S, T, U | семестровые оценки за человека по каждому виду транспорта, в одну сторону |
| V, W | выбранный транспорт и метод/конкретная причина отсутствия расчёта |
| J | расходы участка с учётом количества; суммируются существующим итоговым прогнозом |

Год запуска вводится на «Паспорте» в G23, откуда его получает «Параметры»!C2.
Автоматический подбор может соединить до трёх отдельно оценённых билетов.
В S/T/U путь ограничен одним видом транспорта, в J/V/W допускается сочетание видов.
Считаются также известные внутренние авиапересадки; неизвестные допускаются с
предупреждением. [Подробные правила и новые модули](../docs/automatic-routing.md).
В пустом шаблоне его нет; при заполнении поездки W попросит указать год.

Для цепочки скопируйте транспортную строку внутри таблицы, сохранив A/B/H/I
и формулы J/S:W; укажите следующий участок и тот же ID. Группировка ID действует
в пределах семестра и года набора. Номера должны идти от 1 без повторов и
пропусков; город прибытия предыдущего участка должен совпадать с отправлением
следующего; количество поездок на участках должно совпадать. Возврат — отдельный
участок. Деления тарифа туда-обратно пополам и автоматического удвоения нет.
Кэш авиа может содержать цену сквозного билета с пересадками. Она относится
ко всему участку: не добавляйте к ней повторно отдельные билеты тех же частей.
Автоматический подбор стыковок по времени не выполняется. Для проживания в нескольких городах скопируйте строки
проживания; ночи задаются отдельно для каждого города.

Календарь редактируется в O3:O6 «Параметров цен»: осень с сентября на пять
месяцев, весна с февраля на пять месяцев. Для второго семестра запуска 2027 года
получается февраль–июнь 2028 года. Сначала рассчитывается каждый месяц, затем
равновзвешенное среднее. Неполный семестр не усредняется по имеющимся месяцам.

Текущий кэш авиа имеет приоритет над историческим ориентиром для соответствующего
маршрута/месяца, если базовый год не позже расчётного. Для запроса с багажом
используется надбавка из параметров книги один раз за направление. Если надбавка
не задана/отключена, неизвестный багаж не становится включённым: остаётся резерв
АТОР с известным багажом либо `#Н/Д`. Старые АТОР и новый кэш не усредняются вместе.
В новых авиа-ориентирах сохраняется фактический год вылета 2026/2027: цена 2027
года не переносится назад как наблюдение 2026 года.

ЖД сохраняет классы, фирменность и веса групп. Автобус проверяется независимо
от наличия поезда. Для направлений внутри области наблюдения Росстата применяется
общий индекс пассажирского транспорта как явно подписанный сценарий. Он не
заменяет индекс конкретного вида. Для остальных направлений — макросценарий RUB.
Повторение будущего роста и отсутствие сезонности наземного резерва сохраняются
как ограничения. Методы и причины показываются в W.

**Проживание индексируется.** Свежие предложения Островка из отдельного снимка
фильтруются теми же параметрами `modPriceUpdate`, что и обычный справочник.
Средняя цена, дата, индекс и источники сохраняются в `PlanningHotels` на
«Данных плана». Старая числовая BR без подтверждённой базы не используется.
Индекс гостиниц РФ не применяется за рубежом: там остаётся макросценарий RUB,
без отдельного прогноза курса и местных цен. Годовой сценарий применяется по
числу месяцев от базовой даты, затем усредняется внутри семестра. Сезонность
гостиниц не оценена. Для пребывания нужны явные ночи; пересадка без ночей даёт
ноль. Нормативные лимиты и остальные статьи автоматически не индексируются.
После изменения гостиничных фильтров обновите плановый каталог повторно.

География и ограничения текущего снимка:
[корневой README](../README.md#покрытие-планового-калькулятора-excel).
Список назначений в F расширен; неизвестное название можно ввести вручную,
но без источника цены оно останется `#Н/Д`. Изменение списка не создаёт тариф.

Воспроизведение: `python -m collector.planning_catalog` создаёт оба каталога.
Сбор наземных цен для явных направлений:
`python -m collector.surface --origins branches --destinations Москва --reverse --raw-dir <вне-репозитория>`.
Для авиа: `python -m collector.planning_air --raw-dir <вне-репозитория>`;
12 будущих месяцев, только односторонние тарифы, все возвращённые направления,
пагинация и локальные коды проверяются отдельно. Ни один источник не гарантирует
полноту всех месяцев. Сбор можно возобновлять в тот же UTC-день.

Проверка: `./excel/test-planning.ps1 -WorkbookPath <копия.xlsm>`.
Она открывает книгу только для чтения, временно импортирует тестовые модули
и не сохраняет тестовые значения. Настройки безопасности не меняются.
Проверяются общий Python/VBA-контракт, типы JSON, защита текстовых полей,
багаж, фактический базовый год, индексация проживания, связность цепочки и
передача пропусков в итог. Тестовые модули в рабочую книгу не устанавливаются.

## Если не работает

- «не удалось скачать … HTTP 404» — файл ещё не опубликован или адрес на «Параметрах цен» с опечаткой.
- «не удалось скачать … (ошибка соединения)» — нет интернета/VPN; откройте адрес в браузере.
- «на листе «Параметры цен» не найдены параметры» — переименована строка в колонке A;
  названия параметров должны совпадать дословно.
- Много жёлтых ячеек — смотрите колонку «Пояснение / причина» в журнале: обычно это сбой
