# Костыли и обходные решения

Всё, что сделано «не по-честному»: почему так, чем грозит и как убрать.
Список ведётся вручную — добавляйте сюда каждое новое обходное решение.

Обозначения риска: 🔴 может сломаться в любой день · 🟡 работает, но неточно или хрупко · 🟢 безопасно, просто некрасиво.

---

## 1. Источники данных

| # | Костыль | Почему | Риск | Как убрать |
|---|---|---|---|---|
| 1.1 | **Отели без дат — из HTML Островка** (`__NEXT_DATA__` на странице города, цена «от» за ночь, 5 страниц по 20 отелей) | Официальный API Островка (ETG/B2B) только по договору, Hotellook закрыт 20.10.2025 | 🔴 сменят вёрстку/структуру JSON — сбор отелей ляжет | Договор с B2B.Ostrovok → официальный API (`docs.emergingtravel.com`) |
| 1.2 | **Отели на даты — внутренний поисковый запрос Островка** `POST /hotel/search/v2/site/serp`, имитация браузера: сначала GET страницы (cookies, `regionId`, `searchUuid`, `csrftoken`), потом постраничный опрос, пока не придут результаты | Цены на даты сайт подгружает только этим запросом | 🔴 недокументированный API, может закрыться или потребовать токен; включена защита Qrator (`qrator_msid2`) | Тот же договор с B2B.Ostrovok |
| 1.3 | **Один опорный заезд для цен на даты: +14 дней от даты сбора, 7 ночей** (`HOTEL_WINDOWS=14`, `HOTEL_NIGHTS=7`). Excel берёт ближайшее окно к дате поездки | Каждое окно — ещё ~10 с на город; сбор на произвольные даты из Excel был бы 30–40 минут | 🟡 цена на даты приблизительная, особенно для поездок далеко от опорной даты и в сезон | Добавить окна (`HOTEL_WINDOWS=14,45,75`) или живой поиск по выбранным городам |
| 1.4 | **Яндекс Путешествия и Booking не используются** | Серверы GitHub получают капчу / проверку на бота; обход не делаем | 🟢 | Только официальные API или партнёрские договоры |
| 1.5 | **Поезда — через недокументированный `suggest.travelpayouts.com/search?service=tutu_trains`** | API Яндекс Расписаний цены больше не отдаёт (`tickets_info` пустой), официального API Туту нет | 🔴 эндпоинт может исчезнуть без предупреждения | Партнёрский API Туту / Яндекса |
| 1.6 | **Цены поездов без дат** — минимальная по поезду для каждого класса | Так отдаёт источник | 🟡 «дорога на даты» в Excel для ЖД не меняется | Источник с ценами по датам |
| 1.7 | **Модуль `collector/sources/rasp.py` (Яндекс Расписания) не участвует в сборе** | Ключ получен, но цен нет; оставлен на случай, если понадобится расписание | 🟢 | Удалить или использовать для расписания на сайте |
| 1.8 | **Авиа — кэш поисков Aviasales**, а не живой поиск | Бесплатный Data API отдаёт только кэш за последние дни | 🟡 редкие направления: мало вариантов (Кантхо — 5), цены могут быть устаревшими | Платный/партнёрский живой поиск |
| 1.9 | **Багаж в тарифе неизвестен** → надбавка за багаж константой (задаётся в Excel) | Data API не говорит, включён ли багаж | 🟡 | Источник с признаком багажа |
| 1.10 | **Закрытые аэропорты — вручную «без авиасообщения»** в `cities_overrides.csv` (Воронеж, Белгород, Брянск, Курск, Липецк, Ростов, Таганрог, Шахты, Крым, Анапа, Крымск, Одесса). Ответ API `400 … not flightable` → статус `not_flightable` | Aviasales по одним закрытым аэропортам пишет «not flightable», по другим (Воронеж) просто молчит — без ручного списка макрос держал бы устаревшую цену | 🟡 откроется аэропорт — убрать город из списка | Брать статус аэропортов из справочника, а не вручную |
| 1.11 | **Авиа «на даты» — по неделе вылета** (`air.by_week`: медиана и 90-й перцентиль по вылетам этой недели, пребывание 1–30 ночей) | Точные пары дат в кэше часто пустые | 🟡 длительность поездки не учитывается | Группировать ещё и по длительности, когда данных станет больше |

## 3. Инфраструктура и сбор

| # | Костыль | Почему | Риск | Как убрать |
|---|---|---|---|---|
| 3.1 | **Всё, что ходит на российские сайты, запускается только в GitHub Actions**; на ПК разработчика включён VPN, с него Островок/Туту не открываются | Выход VPN (FI/UK) блокируется сайтами, а IP GitHub — нет | 🔴 если Островок/Туту начнут блокировать облачные IP GitHub — сбор отелей/поездов встанет | Запасной вариант: сбор с российского IP (свой ПК без VPN или VPS в РФ) |
| 3.2 | **Отладочные workflow оставлены в репо**: `dump.yml` (скачать страницы), `probe.yml`, `probe-browser.yml` (Playwright, запись XHR), `probe-serp.yml`, `check-secrets.yml` (длина секретов) и скрипты `collector/probe_*.py` | Единственный способ смотреть на сайты с «чистого» IP | 🟢 | Удалить, когда разработка закончится |
| 3.3 | **Сбор в 4 параллельных потока + объединение** (`collector/merge.py`), файлы потоков передаются артефактами | Отели на даты удлинили сбор до ~2 ч | 🟡 если упадёт один поток, его города останутся из прошлого снимка (`stale`) | — |
| 3.4 | **При сбое источника остаются прошлые данные** с `stale: true`; курсы ЦБ при частичном сборе берутся из прошлого снимка | Чтобы ночной сбой не обнулял таблицу | 🟢 смотрите `updated_at` и `stale` | — |
| 3.5 | **Бот коммитит с `git pull --rebase -X theirs`** | При rebase «theirs» = свежий снимок бота; `ours` затирал бы новые данные старыми | 🟢 | — |
| 3.6 | **`git push` с ПК — только с `http.sslBackend=openssl`** (прописано в `.git/config`) | Windows-библиотека schannel рвёт TLS через VPN | 🟢 только для этого ПК | — |
| 3.7 | **Секреты GitHub залиты из `.env`** (`gh secret set -f .env`) | Вставка в `gh secret set` в консоли Windows сохраняла пустые значения | 🟢 проверка — `check-secrets.yml` | — |
| 3.8 | **Netlify пересобирает сайт на каждый коммит данных** | Так проще всего доставить свежий снимок | 🟡 лимит сборок бесплатного тарифа при частых ручных пересборах | Перевести сайт на чтение `prices.json` с GitHub напрямую |
